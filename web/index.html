Welcome to ByteShrink

Compress smarter. Restore perfectly. Keep your files private.

ByteShrink is a local-first, privacy-focused file compression and decompression utility powered by the Huffman Coding algorithm. It processes files entirely on your device without uploading your documents, images, video, or audio to any external cloud service.

📦

Compress Files

Encode any file using variable-length Huffman codes and store it in the custom .hfx archive format. Real-time statistics display exact bytes saved, compression ratios, and processing speed.

🔓

Decompress Archives

Restore original files bit-for-bit from compatible ByteShrink archives. Built-in IEEE 802.3 CRC-32 checksums guarantee 100% exact file integrity on every decompression pass.

🔬

Algorithm Explorer

Visually inspect the 2D Huffman Tree with pan and zoom. Explore the 256-symbol byte frequency distribution, prefix-free binary codes, and the priority queue's step-by-step greedy merges.

All compression and decompression routines run locally in native C++. Your data never leaves your computer, ensuring complete privacy.

📖 DSA THEORY & COLLEGE EVALUATION REFERENCE GUIDE

1. Core Data Structures & Algorithms in ByteShrink

  • Greedy Algorithm: At each step, selects the two nodes with the smallest frequencies and combines them. This optimal substructure guarantees minimal weighted external path length.
  • Min-Heap / Priority Queue: Stores candidate nodes in a 0-indexed binary heap array with siftUp and siftDown operations running in O(log k) time. Overall tree construction runs in O(k log k).
  • Binary Tree: Represents prefix-free codes where leaf nodes contain byte symbols and branch edges represent binary bits (0 for left, 1 for right).
  • Bit Packing: Packs variable-length bitstrings MSB-first into raw binary bytes with 64KB buffering.
  • Integrity Checksum: IEEE 802.3 CRC-32 polynomial (0xEDB88320) ensures byte-for-byte exactness upon decompression.

2. Time and Space Complexity

PHASE TIME COMPLEXITY SPACE COMPLEXITY EXPLANATION
Frequency Counting O(n) O(1) Single streaming pass over n bytes with fixed 256-element counter.
Min-Heap Construction O(k log k) O(k) Inserting k distinct symbols into priority queue (k ≤ 256).
Greedy Tree Merging O(k log k) O(k) Exactly k - 1 merges combining two minimum nodes.
Code Generation O(k) O(k) Single recursive DFS traversal visiting 2k - 1 nodes.
Bitstream Encoding O(n) O(1) O(1) array code lookup with 64KB I/O buffer.
Bitstream Decoding O(b) O(1) Traversing tree edges for each of the b payload bits.

3. Shannon Entropy & Pre-Compressed Files

Formats such as JPEG, PNG, MP4, MP3, and DOCX (which is a ZIP container) already employ internal entropy coding (such as DEFLATE, DCT quantization, or Huffman coding). Their byte distribution exhibits near-maximum Shannon entropy (~8 bits per byte). Losslessly compressing an already-compressed file cannot reduce it further, and adding the 23-byte archive header and frequency table results in a slightly larger file. ByteShrink explicitly identifies and reports this honest physical reality.
